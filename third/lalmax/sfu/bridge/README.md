# SFU bridge media adapters

`H264` converts one authorized, sequential packetization-mode 1 H.264 RTP stream to Annex-B `base.AvPacket` values. The output can be passed to a lal custom publisher configured with `VideoFormat = base.AvPacketStreamVideoFormatAnnexb`. Parameter sets are cached and prepended to IDR access units; output waits for SPS, PPS and an IDR. Packet gaps, malformed frames and parameter changes force another IDR before output resumes. Duplicate and late packets are dropped. Sequence and timestamp wrap are handled.

The embedding application must authorize and own the Room subscription, validate the negotiated codec and source identity, request keyframes and manage the custom publisher. Slice inspection does not prove full bitstream conformance or rule out every form of frame reordering. `H264` is single-threaded and accepts only one SSRC. It rejects B slices, malformed slice headers and unsupported partitioned/extension slices, and maps PTS and DTS to the same 90 kHz-derived millisecond clock. It does not synchronize audio, recover reordered packets, transcode, create a Group, or start a bridge. Timestamp regression and SSRC changes are errors; callers should terminate the binding and establish a new one. This component alone does not complete the GroupBridge integration.

`Opus` converts a single 48 kHz Opus RTP stream to independently owned audio `AvPacket` values. It ignores late or duplicate packets and RTP padding; it does not reorder packets, conceal losses, validate Opus bitstreams, or establish a shared clock with video. The caller validates negotiation and must terminate the binding on timestamp regression or SSRC change. `RunOpusToLal` publishes one authorized audio track to its own Group; it does not combine tracks or synchronize audio and video.

`RunH264` consumes an already authorized `rtpforward.Subscriber` and sends decoded frames to a caller-provided sink in order. It owns and closes the subscription when it returns. Cancellation, source termination, malformed input and sink errors stop the runner; the runner checks for terminal subscription errors before decoding each buffered packet. The sink should honor context cancellation when possible, and must copy payloads it retains after returning. A blocked sink can delay runner shutdown; the fanout's bounded queue still disconnects it without blocking the source or other subscribers. A slow-subscriber error is observed when the sink returns. The caller owns authorization, keyframe requests, Group lifecycle and integration with a real publisher.

`RunH264ToLal` connects an already authorized RTP subscriber to a single video-only lal custom publisher in the `live` app. The caller must authorize and validate the target name and source before invoking it. An occupied input returns the lal registration error; the subscriber is closed on registration failure. The custom session and subscriber are released when the call returns. This does not establish Room subscriptions or request keyframes. `FeedAvPacket` is synchronous and has no context cancellation: if lal processing blocks, the call and cleanup wait for it, while fanout keeps other subscribers isolated.

Trusted services can use `access.Session.StartH264Bridge` with a dedicated system participant and an existing authorized subscription. It rechecks subscribe and `manage_bridge` permissions with publication metadata and target Group; the policy must validate target ownership and namespace. The returned channel reports asynchronous startup and runtime failures. The service must validate negotiated H.264 fmtp and no-B-frame constraints, cancel on policy revocation, and avoid treating a returned channel as proof that a publisher has started. Unsubscription and session close cancel the binding; blocking lal writes can delay its termination.

For a service that authorizes a short-lived request but keeps a bridge running afterward, `StartH264BridgeWithContexts` accepts separate authorization and lifetime contexts. Cancellation of the request after setup does not stop the bridge; the service must cancel the lifetime context when stopping, shutting down, or revoking access.
