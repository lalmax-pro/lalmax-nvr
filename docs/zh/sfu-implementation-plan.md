# SFU 分批实施计划

跟踪：[Issue #93](https://github.com/lalmax-pro/lalmax-nvr/issues/93)。每一批应独立验证；除已注明的部分外均为待实现。

1. **Room 核心**：独立的内存房间管理、命名空间、房间代次、成员加入退出和容量限制。已实现基础模型；支持可配置的成员、每成员发布、订阅和观察者数量限制；鉴权、自动过期和重连尚未实现。
2. **发布与订阅模型**：Track 身份、发布/取消、订阅/取消、成员退出时的资源清理已实现；内部快照与有界事件流已实现；跨连接重放、鉴权过滤与信令传递待后续完成。
3. **信令与授权**：WebSocket 房间协议、服务生命周期、NVR 鉴权适配、容量与超时处理。必须服务端检查每次操作的权限。
4. **纯 SFU 媒体链路**：Pion 传输，H.264/Opus 发布与转发，RTCP 和关键帧请求；用两个真实 WebRTC 客户端验证双向收发与房间隔离。
5. **GroupBridge**：选定音视频 Track 异步发布到 lal Group，处理时间戳、资源清理、拥塞隔离和冲突；验证桥接启停不影响会议。
6. **Meet Demo**：`tools/sfu-meet` 的入会、设备预览、多成员画面、屏幕共享、Track 和桥接控制；对接真实信令并进行浏览器联调。
7. **稳定性与质量**：重连、弱网恢复、带宽估计和选层、TURN、压测和长期资源泄漏检查；再评估摄像头 Group 到 SFU 的适配。

第一批当前仅是内部状态模型，尚无网络入口或可用的 SFU 会议功能。Room 空闲回收、连接代次和快照/事件一致性将在后续信令生命周期批次完成。
