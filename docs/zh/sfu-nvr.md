# NVR SFU 会议（实验功能）

在配置文件中启用 `sfu.enabled: true`，并使用内嵌媒体引擎，重启 NVR 后访问 `/sfu-meet/`。使用 NVR 超级管理员账号入会，浏览器采集摄像头、麦克风或屏幕需要安全上下文（HTTPS 或 localhost）及相应权限。WebSocket 使用一次性短期入会凭证；配置文件密码不会放入信令 URL。

会议页面默认使用 `default` 内存房间，也可以创建、刷新、选择和关闭其他房间。会议采用 Opus 和 H.264；一条会议视频、麦克风轨道或同一成员的音视频组合可手动桥接到独立 lal Group，通过页面内 WHEP 播放。组合桥接依赖发布端 RTCP Sender Report；尚未完成音视频同步误差及长期运行验收。桥接会在源结束或授权失效时停止，重启后不自动恢复。服务会保留历史桥接输出身份，以防重启后误将旧身份当成普通未保护流。

H.264 通用录像器的进程内帧路径可写入 Opus 音轨，包括音频晚于视频出现的情况。合成音视频消息已通过真实 lalmax Group、帧订阅和录像器生成 MP4 并检查音轨；从 SFU 发布到实际录像计划的完整链路、真实媒体播放和音视频同步尚未完成验收，纯音频桥接的录像也不在此结论中。

可选的 `sfu.ice_servers` 为 SFU 服务端和浏览器配置 STUN/TURN，格式见配置示例；不配置时依赖直接可达的 ICE 地址。TURN 凭据随一次性入会凭证响应提供给已授权的会议管理员，应使用 HTTPS 和限定权限、有效期的凭据。WHEP 媒体服务使用自身 ICE 配置，浏览器播放器使用上述服务器；不同网络拓扑仍需分别验证。

Meet 在信令断开或媒体连接失败时会最多尝试三次重连，申请新票据并校验房间代次；媒体连接短暂中断时先等待 10 秒，若自行恢复则继续使用原连接，否则触发重连。它保留仍存活的摄像头、麦克风和静音状态，屏幕共享需要手动重新开启。断线时页面尝试停止本页面的桥接，重连后再次尝试清理；如果创建响应丢失，会用原请求键查询并清理对应桥接。持续断网、查询不到请求或请求长期未完成时，页面会提示在“我的桥接”检查。桥接不会自动恢复。点击离会会取消重试并释放设备。跨 NAT、弱网、扩容、重连、音视频同步及生产环境容量仍待真实场景验证。媒体引擎实例被替换时，会议服务会关闭，需重启 NVR 后恢复。不要把实验功能视为已完成 Issue #93 的全部验收。


管理员可以通过受保护的 NVR API 管理额外的临时纯 SFU 房间：

- `GET /api/sfu/rooms/` 返回房间 ID、代次和当前人数；`POST /api/sfu/rooms/` 接收 `{"id":"room1"}` 创建房间。
- `POST /api/sfu/ticket` 接收 `{"room_id":"room1"}` 签发该房间的一次性入会凭证；省略 `room_id` 保持默认房间的既有行为。可附带列表返回的 `room_generation`；若房间已关闭并同名重建，票据请求会被拒绝，需重新刷新列表。
- `DELETE /api/sfu/rooms/room1?generation=<代次>` 关闭指定代次并断开其会话。默认房间不能通过该接口关闭；旧代次的票据和关闭请求不能用于重建后的同名房间。

房间 ID 仅允许 1–64 个英文字母、数字、下划线或连字符；最多 32 个房间（含默认房间）。房间不会持久化，NVR 重启后额外房间需重新创建。此批接口仅供超级管理员使用，会议页面在加入期间锁定房间选择，离开后可选择其他房间。桥接 API 按发布轨道所属房间路由；音视频组合必须来自同一房间的同一发布者。关闭房间会终止该房间的桥接并撤销播放授权，不影响其他房间。

`GET /api/sfu/bridges/` 列出当前管理员拥有且有权查看的桥接，包含 ID、发布轨道和状态，不包含播放凭据。断网恢复后可在会议页面的“我的桥接”中刷新列表、停止桥接并在终态删除记录；也可对目标调用 `POST /api/sfu/bridges/<id>/stop`，等待状态变为 `stopped` 或 `failed`，再调用 `DELETE /api/sfu/bridges/<id>` 移除记录。列表跨当前活动房间，属于瞬时快照；房间关闭、桥接被清理或 NVR 重启后，记录可能不再存在。

创建桥接时可设置 `Idempotency-Key` 请求头，值为 1–128 位英文字母、数字或 `-_.~`。同一管理员用相同键和相同轨道重试会复用创建结果，并重新检查查看权限；用同一键提交不同轨道返回 409。请求断开不会取消已接受的创建，可用相同键查询结果；失败结果也会保留，请在需要重新发起操作时使用新键。结果在进程内保留至完成后 24 小时，最多 4096 条，满时新键返回 429；重启或过期后不再保证去重。桥接已删除或房间已关闭时，重试返回 404，不会在保留期内重新创建。会议页面在创建请求出现网络错误时使用同一键最多尝试三次；如离会后才获取桥接 ID，会尝试停止并删除该桥接。网络持续不可用时，请在“我的桥接”检查遗留桥接。

`GET /api/sfu/bridge-requests` 使用 `Idempotency-Key` 请求头只读查询当前管理员自己的创建请求，不会发起创建；请求仍在处理时返回 202 和 `{"state":"pending"}`，已完成时返回 200 和桥接状态。未知、已过期或已清理的请求返回 404；404 不能证明网络中较晚到达的创建请求不会生效。页面尝试清理时会短暂重查，仍无法确认则提示人工检查。返回值不包含播放凭据，需重新通过当前身份及查看权限检查。

可选配置 `sfu.idle_timeout`（例如 `10m`）可在空闲宽限期后自动关闭非默认房间；留空时不自动回收。房间只要仍有成员（包括运行中的桥接订阅者）就不会被视为空闲，回收会清理该房间的桥接注册表。默认房间始终保留。

Meet 的“网络诊断”面板展开时展示浏览器近期收发媒体负载码率、接收方向丢包率和选中 ICE 链路的往返时延；关闭面板或离会后停止采样。浏览器未提供某项数据时显示 `—`，这些数值不等于服务端容量或完整链路带宽。
