# SFU 桥接录像时间轴边界

MP4 封装器为多条轨道选择最早的首个解码时间作为公共起点，并用 edit list 表示其他轨道的首包延迟。Opus 轨道在源音频前加入 80 毫秒合成静音作为解码预热，再通过 edit list 跳过这段预热；源音频开头不会被当作预热裁掉。轨道起始时间必须来自同一个时间基准，不同来源的时钟不能直接比较。

可复现的结构样本：

```sh
SFU_OFFSET_TEST_MP4=/tmp/sfu-offset.mp4 go test ./internal/muxer -run '^TestMP4TrackEditPreservesLateOpusOffset$' -count=1
ffprobe -v quiet -show_entries stream=codec_name,start_time,duration -of json /tmp/sfu-offset.mp4
```

样本的视频和音频输入首包分别位于同一时钟的 1000 毫秒与 1200 毫秒。当前本机 `ffprobe` 显示视频起始为 0 毫秒、Opus 起始为 200 毫秒。Opus 媒体样本表包含预热包，媒体轨道时长与经过 edit list 的有效播放时间可能不同；不要把预热包算作源媒体。样本视频 NAL 仅用于结构测试。

已登记的 SFU 桥接输出在 H.264 进程内录像路径中使用源视频时间戳和同一来源的音频时间戳；其他流及 RTSP 回退保持原有墙钟行为。暂停后的预录帧不含源时间，包含预录帧的当前片段继续使用墙钟；下一片段可恢复源时间。

对使用源时间的 Opus 音轨，录像器会为不超过 60 秒且与 2.5 毫秒对齐（允许 1 毫秒舍入误差）的中途间隙插入静音。长间隙优先使用由六个 20 毫秒 CELT 帧组成的 120 毫秒 Opus 包，余量再使用 20、10、5 和 2.5 毫秒包；一次最多约 500 个补包。补包已通过 FFmpeg 离线解码。静音只能保留时间轴，不能还原丢失的声音。超过上限或无法对齐的间隙会记录警告，仍可能造成漂移；不会影响会议转发。

音视频桥接按两条轨道各自的进度排序，在一条轨道停滞时等待约 500 毫秒后继续输出；队列仍有限额，超过等待窗口的迟到媒体可能被丢弃。这个等待可能增加桥接延迟，不改变纯 SFU 转发链路。

Opus 音轨采用 48 kHz 媒体时间基准，以保留 2.5 毫秒等非整数毫秒帧的时长；movie 时间基准仍为毫秒，因此轨道起始和最终总时长仍存在约 1 毫秒的量化。该选择与 [Opus ISOBMFF 封装说明](https://opus-codec.org/docs/opus_in_isobmff.html)中的媒体时间基准一致。本机合成媒体验证的运行方式和范围见[桥接录像验证](sfu-bridge-recording-validation.md)；真实设备、其他播放器、弱网和更长时间同步仍待验收。
