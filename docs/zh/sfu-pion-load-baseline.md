# SFU 本机 Pion 传输负载基线

此可选测试启动独立 Meet Demo 服务子进程，并在测试进程运行 1 个发布端和多个 Pion 观看端，经真实 WebRTC 连接转发合成视频 RTP。它不打开媒体设备、解码视频或播放音频。默认每包包含 1000 字节合成 H.264 载荷，发送速率约 30 包/秒；载荷仅用于传输测试，不代表可解码视频。普通 Demo 房间上限为 8 个成员；负载测试可为每个场景创建最多 32 人的隔离测试房间。

默认复现（1、4、7 个观看端，每组测量 10 秒）：

```sh
SFU_LOAD_TEST=1 SFU_LOAD_VIEWERS=1,4,7 SFU_LOAD_DURATION=10s go test -v ./tools/sfu-meet -run '^TestDemoSFULoad$' -count=1
```

`SFU_LOAD_VIEWERS` 可指定逗号分隔的 1–31 个观看端数量；每个子场景使用发布者加观看端数量配置独立 Room，不改变 Demo 默认上限。`SFU_LOAD_DURATION` 可设为 `1s` 至 `30m`；默认每组 5 秒。`SFU_LOAD_PPS` 可设为 1–1000，`SFU_LOAD_PAYLOAD_BYTES` 可设为 100–1200；默认 30 包/秒、每包 1000 字节。需要本机非回环 IPv4 接口和 UDP，资源采样不可用时测试会报告错误或将 CPU 标为 unavailable。默认运行 `go test` 时此负载测试跳过。首包计时从发起订阅到收到第一包 RTP，包含信令和 ICE，但不包括视频解码与渲染。

## 2026-11-10 Chrome 真实媒体冒烟验证（非容量测试）

本机 standalone Demo 使用一名发布成员和一名仅观看成员。发布端采集真实摄像头与麦克风，观看端显示实时摄像头画面并发现 `video/H264`、`audio/opus` 轨道；发布端在通话中切换麦克风后，远端连接与两条已发布媒体仍保持。将发布端当前 Meet 标签页选作共享来源后，观看端收到独立 H.264 屏幕轨道；停止共享移除该轨道，摄像头与麦克风继续工作。视频订阅取消/恢复成功，最后两端正常离会并释放媒体。

短时浏览器统计样本为接收负载约 1.01–1.76 Mb/s、接收丢包率 0%、回环 RTT 0–1 ms。统计值在不同观察时刻采集，包含摄像头、屏幕或两者的媒体负载，不是固定码率基准。该试验只覆盖同机 Chrome 双标签页和本机 SFU；未人工听音、未量测音画同步误差、未经过 NVR GroupBridge/录像链路，不包含弱网、跨 NAT、公网、长时间或多观看端真实解码，因此不构成容量或生产验收。

2026-11-10 在摄像头三层 Simulcast 接入后补做 Chrome 实机复测：真实摄像头与麦克风从发布标签页发出，第二个本机标签页收到 H.264/Opus；摄像头订阅取消后远端画面移除，恢复订阅后画面重新到达。浏览器按 RID 的短时发送码率样本为 l 12–30 kb/s、m 35–97 kb/s、h 0 kb/s；样本间有变化，且 h 始终未观察到非零发送。因此已确认浏览器报告 RID 统计且 l/m 在发包，尚未验收 h 层实际发送或三层完整上行。两端同机回环 RTT 为 0–3 ms；这不是弱网试验。

补齐 NVR 和 Meet 的入站 Transport-Layer-CC 反馈拦截器后再次查看发布端网络面板，观测样本为 l 16 kb/s、m 49 kb/s、h 0 kb/s。配套 Pion 回归确认发布端入站 RTP 收到非空 TCC 反馈；这修复了 GCC 的协议输入路径，但该 Chrome 样本仍未观察到 h 层发送。新增的 RID 编码状态字段落地后尚未重新进行浏览器采样，因此帧数、分辨率和质量限制原因仍无实机结果。

本次也将发布标签页画面作为共享来源，第二标签页收到独立 H.264 屏幕轨道；停止共享后该轨道从远端列表清理，摄像头与麦克风轨道仍在。两端正常离会，摄像头、麦克风和共享采集均已释放。验证仍只覆盖同机 Chrome 双标签页和 standalone Demo；未人工听音、未测音画同步、未经过 NVR GroupBridge/录像链路，不包含弱网、跨 NAT、公网、长时间或多观看端真实解码，因此不构成容量或生产验收。
