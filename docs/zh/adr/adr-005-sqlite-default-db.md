# ADR-005：SQLite 为默认数据库，支持 PostgreSQL / MySQL 切换

- **状态**：Accepted
- **日期**：2026-10
- **关联**：[数据库迁移文档](../database-migration.md)

## 背景

NVR 需要持久化摄像头配置、录像索引、事件记录、转码任务等数据。需要决定默认数据库方案及多数据库兼容策略。

## 备选方案

**方案 A：仅支持 SQLite**
- 零运维，单文件，嵌入式
- 代价：并发写入性能受限（WAL 模式可缓解），不适合多实例 / 高并发场景

**方案 B：PostgreSQL 或 MySQL 为主**
- 性能强，支持高并发写入和复杂查询
- 代价：需要额外运维数据库服务，提高了部署门槛

**方案 C：SQLite 为默认，支持 PostgreSQL / MySQL 切换**
- 小规模部署：零依赖，开箱即用
- 大规模或高可用部署：切换到生产级数据库
- 代价：需要维护多数据库兼容的 SQL，避免使用数据库特有语法

## 决策

选择**方案 C**：SQLite 为默认，通过配置切换到 PostgreSQL 或 MySQL。

实现约束：
- `internal/storage` 使用 `database/sql` 标准库，不引入 ORM
- 所有 SQL 兼容三种数据库方言，避免 `RETURNING`、`UPSERT` 等特有语法
- 迁移版本管理在 `db.go` 中按版本顺序执行 DDL

## 权衡与已知限制

- SQLite WAL 模式下并发读性能良好，但高频写入场景（大量摄像头同时录像）建议切换到 PostgreSQL
- 跨数据库驱动迁移（SQLite → PostgreSQL）需要导出 / 导入，不支持热迁移（工具链见数据库迁移文档）
- 含转码数据的跨驱动迁移尚未完整验收（截至 2026-10），不列为已验证能力
