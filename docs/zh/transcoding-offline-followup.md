# P5 独立工作项：历史录像离线转码

关联 [通用实时转码 Issue #66](https://github.com/lalmax-pro/lalmax-nvr/issues/66)。

状态：设计边界已经确定，**离线转码不属于 Issue #66 的实时交付范围**。不得把直播任务或编码器配额直接复用于离线任务。Fork 当前未启用 GitHub Issues，另立 Issue 需要在维护者启用后创建；此文可直接作为独立 Issue 的正文。

## 目标

对已经写入 NVR 存储并登记在数据库中的录像进行受控离线转码，产出新的录像对象，原件默认保持不可变，完整记录来源、实际音视频编码、文件哈希、任务重试和执行环境。

## 必须满足的功能与安全边界

1. **输入授权**：只接受授权的 `recording_id`，由数据库和 storage root 解析文件；拒绝任意文件路径、URL、重定向、符号链接逃逸以及任意进程参数。
2. **独立队列**：`queued/running/failed/completed/canceled` 状态与独立版本水位、任务租约、最大重试次数和限速，不能占用直播专属配额或抢占实时流。
3. **固定模板**：仅允许经过版本化验证的编码模板；若选用硬件编码器，必须实测可用，失败不得静默回退软件编码。
4. **可靠写入**：写入临时文件、ffprobe 和实际解码检查、fsync、原子重命名、随后提交新的 DB 对象及来源关系；失败清理残留，不能覆盖原文件。
5. **恢复与隔离**：独立 Worker 身份和私有控制通道，父进程故障恢复后不得出现重复生成、旧代次回调、遗留转码进程或失效凭据。
6. **结果追溯**：记录 source_recording_id、target_recording_id、音视频 codec、编码器、Profile Revision、尺寸、时长、字节数、哈希及完成时间。
7. **验收**：损坏输入、磁盘满、重启、取消、权限撤销、并发删除、数据库故障、硬件不可用，以及 SQLite/PostgreSQL/MySQL 迁移与恢复。

## 非目标

- 不因实时转码 Issue #66 合并而自动启用离线处理。
- 不复用实时 DemandLease、WHEP 会话或受保护 RTMP 回灌地址。
- 不自行修改、压缩或删除原始录像。

## 验收提交要求

独立的源码 PR、幂等/故障注入/race 测试、真实媒体输入输出及解码记录、资源配额与设备矩阵、回滚说明齐备后方可合并。
