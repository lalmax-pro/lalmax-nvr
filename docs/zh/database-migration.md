# 数据库配置与迁移

lalmax-nvr 使用数据库保存设备配置、录像索引、事件、VoIP 通话记录等应用状态；录像媒体文件仍保存在配置的存储目录中。默认使用 SQLite，无需单独部署数据库服务。PostgreSQL 和 MySQL 也可作为活动数据库。

## 配置数据库

新部署保持 `storage.database_driver` 和 `storage.database_dsn` 未设置，即使用 `{storage.root_dir}/lalmax-nvr.db` 中的 SQLite。若直接使用 PostgreSQL 或 MySQL，在配置文件中同时设置这两个字段。DSN 属于敏感信息；配置 `NVR_ENCRYPTION_KEY` 后，lalmax-nvr 保存配置时会加密 DSN。

也可以在 Web **设置 → 数据库迁移** 页面测试并保存 PostgreSQL 或 MySQL 目标连接。数据库账号需要在目标库中创建表和索引、读写数据的权限；请先创建目标数据库本身。

## 在 Web 中从 SQLite 迁移

1. 备份 SQLite 文件，并确认 PostgreSQL 或 MySQL 目标数据库为空。
2. 打开 **设置 → 数据库迁移**，选择目标数据库、填写 DSN、测试连接并保存目标配置。
3. 点击 **迁移并切换** 并确认。迁移期间存储操作会等待。lalmax-nvr 会初始化目标库、分批复制各表数据、核对逐表行数，并校准 PostgreSQL 自增序列。
4. 成功后，当前进程切换到目标连接，并把目标记录为活动数据库；原 SQLite 文件会保留。

迁移接口会在完成后返回各表复制行数。目标库不能含有无关或需要保留的数据：迁移会拒绝非空目标，也会拒绝无法识别为本应用中断迁移的库。

如果复制期间进程停止，目标事务会回滚已复制的数据；迁移标记允许对同一目标重试。如果复制完成但配置保存失败，当前仍使用 SQLite；重试时会重新复制最新源库数据。迁移期间数据库操作暂停，避免复制和切换之间出现丢失的写入。

## 当前支持范围

Web 迁移流程当前支持 **SQLite 迁移到 PostgreSQL 或 MySQL**，暂不支持 PostgreSQL 与 MySQL 之间互迁，也不会移动录像文件或删除 SQLite 源文件。确认目标库正常运行前，请保留源库备份。
